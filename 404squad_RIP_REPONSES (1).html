2. Mission, règles et planning

Atlas Sécurité exploite quatre agences. Votre cellule réseau doit rétablir les communications, absorber une panne, puis contenir une injection de routes. Vous travaillez dans un seul projet Cisco Packet Tracer, sauvegardé à chaque étape. Les défis demandent des actions et des preuves observables.

Durée : 240 minutes · 12 défis · 1 000 points · équipes de 2 à 3. Faites tourner les rôles opérateur CLI, analyste et responsable des preuves tous les trois défis. Les durées indiquées sont des objectifs, pas des délais éliminatoires.

Règles de validation

  • Chaque défi comporte un bloc « Flag à saisir sur Academia ». Après avoir réalisé les manipulations et conservé les preuves demandées, saisissez le code indiqué dans le défi correspondant sur Academia.
  • Pour que le défi soit comptabilisé sur Academia, saisissez son flag exact puis validez la soumission. Les codes sont FLAG_C01 à FLAG_C12, en majuscules, avec un tiret bas et sans espace. Cocher votre suivi dans cet énoncé ne soumet pas le flag à Academia. Les points sont accordés une seule fois par défi.
  • Deux indices facultatifs sont intégrés à chaque défi : ouvrez d’abord l’indice 1, puis le 2 si nécessaire. Ils ne retirent pas de points. Indiquez les indices utilisés dans votre carnet pour le débriefing.
  • En cas de blocage de plus de 8 minutes, demandez une reprise : un état sain peut être fourni après les défis 3, 6 ou 9. Cela permet de poursuivre, sans attribuer les points des défis non démontrés.
  • Les routes interagences et les deux réseaux techniques doivent être apprises par RIP. Seule R-TAZ peut porter une route statique par défaut ; les routes préconfigurées du FAI sont hors périmètre.
  • Ne modifiez ni les minuteurs RIP ni les distances administratives. N’utilisez ni OSPF, ni redistribution générale de routes statiques, ni coupure du routeur d’injection pour contourner un défi de défense.
  • L’équipement d’injection n’est modifiable qu’à l’étape d’activation prévue au défi 8 ; le FAI reste hors périmètre. Toutes les actions restent confinées au fichier Packet Tracer.
Point de départ : le projet .pkt fourni contient les équipements, le câblage et l’adressage. Le schéma et les tableaux de cet énoncé sont vos références pour identifier les interfaces et contrôler vos résultats.

Academia enregistre les points lorsque le flag du défi est accepté. Note sur 20 = total des points / 50. Les preuves et le compte rendu documentent les manipulations réalisées. Les champs de suivi de ce document servent à votre compte rendu ; consultez Academia pour connaître les points enregistrés.

4. Outils et méthode de travail

Sur un routeur, ouvrez l’onglet CLI. Sur un PC ou un serveur, utilisez Desktop → Command Prompt pour les tests. Appuyez sur Entrée si la console attend une interaction ; utilisez enable pour accéder aux commandes de vérification privilégiées.

Commande / outilUtilité
show ip interface briefComparer adresses et états des interfaces
show ip routeVoir toutes les routes installées, dont la route par défaut
show ip route ripAfficher les routes apprises par RIP
show ip route 192.168.70.0Examiner le chemin vers Nador ; vérifier le préfixe et le masque affichés
show ip protocolsLire version, réseaux déclarés, interfaces passives et minuteurs
show running-configExaminer la configuration actuelle du routeur
debug ip rip puis undebug allObserver temporairement les annonces, puis arrêter le débogage

tracert <adresse> sur un PCObserver le trajet depuis le poste ; sur un routeur, utiliser traceroute si disponible
Mode Simulation → filtre RIPInspecter les mises à jour ; distinguer temps simulé et temps réel
copy running-config startup-configConserver la configuration de l’équipement ; confirmer le nom proposé
File → Save / Ctrl+SSauvegarder le projet Packet Tracer complet

Pour chaque observation : prédisez → vérifiez → modifiez → testez → expliquez. Laissez passer les échanges nécessaires avant de conclure. Les premiers pings peuvent être affectés par la découverte des adresses de couche 2. Le nombre d’échecs et les délais doivent être observés sur votre poste, sans inventer une valeur attendue.

Une copie d’écran exploitable montre le nom de l’équipement, la commande et son résultat. Nommer les captures C03_R-TAZ_route.png, C08_R-GUE_avant.png, etc. Évitez les captures de tout l’écran lorsque l’information utile devient illisible.
